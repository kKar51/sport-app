# Журнал зала

Веб-приложение для телефона: подходы, утренний вес, талия, пробежки. Ставится на экран «Домой» на iPhone и работает без сети.

Данные не хранятся в этом репозитории. Приложение пишет их через GitHub API в отдельный **приватный** репозиторий владельца. Токен вводится в настройках приложения и остаётся только на устройстве.

## Формат данных в приватном репозитории

| Файл | Что внутри |
|---|---|
| `program.json` | Программа: фазы цикла, расписание, упражнения, ориентиры |
| `workouts/ГГГГ-ММ-ДД.json` | Тренировка за день: тип, подходы `{w, r}`, пробежка, заметка |
| `body/ГГГГ-ММ.json` | По датам за месяц: утренний вес, шаги, талия, низ живота |
| `food/ГГГГ-ММ.json` | По дням: отмеченные приёмы пищи, сладкое, принятые добавки |
| `health/ГГГГ-ММ-ДД.json` | Отдельный импорт сна и шагов; ручные записи не заменяет |
| `food/estimates/ГГГГ-ММ.json` | Оценки ккал и белка из недельного разбора; журнал только читает |
| `health/auto/ГГГГ-ММ-ДД.txt` | Текст `SPORT_HEALTH_V1`, который команда iPhone отправляет сама; журнал только читает |

## Установка на iPhone

1. Открыть сайт приложения в Safari.
2. «Поделиться» → «На экран „Домой“».
3. Открыть приложение с иконки → настройки → вставить fine-grained токен GitHub с доступом `Contents: Read and write` только к приватному репозиторию с данными.

Код без зависимостей и сборки: `index.html`, `app.css`, `app.js`, `sw.js` и отдельные модули импорта и графиков.

## Быстрый ввод и графики · версия 9

Главная открывается с датой и полями веса, сна и шагов. Сон вводится часами и минутами; в JSON по-прежнему сохраняются десятичные часы. Замеры талии и низа живота раскрываются отдельно. Последний вес показывается с датой под полем и не подставляется вместо сегодняшнего значения.

Изменения формы сохраняются локально в `dailyDrafts` прежнего ключа `sport-journal.v1`. Они переживают переходы, смену даты и офлайн-перезапуск, не изменяя файлы дневника или очередь GitHub до явного «Сохранить». Проверка всех изменённых полей выполняется до записи; сохраняются только изменённые показатели. Пустое новое поле не становится нулём. Явная очистка существующего ручного значения убирает только его, сохраняя отдельный импорт Health. При изменении исходного ручного значения во время синхронизации сохранение черновика останавливается до отмены/повторного ввода. Форма привязана к показанной дате и исходным значениям, включая случай полуночи или открытой клавиатуры.

При первом запуске версии 9 прежняя локальная строка дополнительно сохраняется в `sport-journal.backup.before-daily-v1`. Более ранняя копия Night Lime остаётся на месте. «Копия до обновления» отдаёт свежую копию перед новой формой; скачивание текущей копии включает черновики и исключает токен.

Название показателя со значком графика открывает динамику, цифровое поле редактируется отдельно. Для веса, сна, шагов, талии и низа живота доступны 7 дней, 30 дней и весь цикл. Нажатие на график или дату в списке показывает значение, источник и переход к исправлению записи. Графики строятся по сохранённым данным, а черновик остаётся на главной.

Вес: отдельные измерения и среднее за 7 дней (не менее 4 измерений); сравнение недель требует по 4 измерения. Шаги: столбики, ориентир программы, среднее за 7 завершённых дней; сегодняшний день отмечен неполным. Сон: длительность по ночам и диапазон программы. Сравнение недель сна/шагов требует минимум 5 дней в каждой. Пропуски не превращаются в нули; рядом показывается число известных дней. Замеры отображаются точками; сравнение за 4 недели использует ближайший замер 21–35 дней назад и показывает фактические даты.

История упражнения показывает реальные лучшие подходы, отдельные режимы веса/повторов, календарные периоды и переход к тренировке. Замены упражнений считаются отдельно. Сопоставляются одинаковые повторы либо одинаковый вес; неизвестный рабочий вес не изображается как 0. Изменение веса тела не окрашивается автоматически как успех или неудача; длительность сна не выдаётся за оценку его качества.

Проверки: `node tests/daily-progress.cjs` и `node tests/progress-unit.cjs`, а также прежние mobile/data-preservation/health. Все тестовые записи синтетические, профили браузера изолированы. Физический iPhone Safari/PWA и нативная клавиатура требуют отдельной проверки.

## Ночной лайм · версия 7

Стартовый экран «Обзор» показывает результаты из существующих записей. Три основные вкладки: обзор, тренировка и еда. Вес и замеры, история и программа открываются из обзора. Вся тренировка остаётся одним списком. Системный шрифт и тёмная палитра работают без загрузки внешних шрифтов.

Схема JSON и ключ `sport-journal.v1` не изменены. При первом открытии версии 7 прежний локальный снимок, включая очередь отправки, копируется в `sport-journal.backup.before-night-v1`. Снимок не заменяется при последующих запусках. Если браузер не разрешил создать копию, в настройках показывается сообщение. В настройках можно скачать текущие записи или копию до обновления; файл включает пути, SHA и очередь, но исключает токен. Автоматического импорта этих файлов в интерфейсе пока нет.

Синхронизация повторно проверяет локальные правки после загрузки файла. При конфликте с другой версией на GitHub она сохраняет локальную очередь и останавливает отправку; удалённый файл не перезаписывается. Если удалённое содержимое уже совпадает с отправляемым, запрос считается выполненным. Обновление оболочки не очищает localStorage и не перезагружает открытый редактор принудительно.

Автоматический расчёт произвольной еды в эту версию не входит. Неуказанные калории и белок отмечаются отдельно от нулевых значений.

## Адаптивный прогресс · версия 14

**Вес.** Цель недели считается от фактического среднего прошлой недели минус выбранный темп (`goals.weight.perWeek`, кг в неделю; 0 — держать вес, минус — набор). Меньше 4 замеров за неделю — цепочка продолжается от цели. Кольцо, карточка и обзор показывают один и тот же коридор текущей недели. Темп меняется на «Прогрессе» → «Темп цели» и записывается в `program.json`. Совет недели — правила программы: быстрее коридора +150–200 ккал, выше коридора вторую неделю — шаги, потом −150 ккал.

**Тренд и прогноз.** Линия тренда — локальная линейная регрессия с гауссовыми весами (σ 3,5 дня): она не отстаёт от равномерного снижения, как скользящее среднее. Темп — наклон за 3 недели (от 5 замеров на отрезке не короче недели) с ошибкой. График идёт от первого замера до «сегодня + 7 дней»; будущее — прогноз с 80 % коридором, который сужается с каждым замером. Нажатие на график показывает день, замер и тренд.

**Сила.** Основные упражнения берутся из слотов `goals.lifts` и следуют выбранной замене. Только рабочие подходы: легче 70 % рабочего веса — разминка. Подтягивания считаются с весом тела, гравитрон и упражнения с блином на теле — без 1ПМ. После трёх тренировок строится логарифмическая кривая `a + b·ln(1 + дни)` с прогнозом на 2 недели. `goals.prior` — уровень до перерыва, по нему процент «от прежнего». «Сила и вес» — изменение в процентах от начала: средняя сила по упражнениям и тренд веса.

**Объём.** «Мышцы» — рабочие подходы в неделю на 16 групп: основная мышца 1, вспомогательная ½ (дробный подсчёт, Pelland et al., 2024), шкала 4 / 10 / 20 (Schoenfeld et al., 2017), отметка прошлой недели, листание недель. «Тренировки» — тоннаж рабочих подходов, каждая тренировка сравнивается только с прошлой такой же. Каталог мышц и инвентаря — `muscles.js`; упражнение вне каталога сопоставляется по названию.

**Гриф.** Вес штанги записывается общий, с грифом. Для штанги и EZ под целью показана раскладка блинов на сторону; гриф 20 и 10 кг можно переопределить в `program.json → equipment {bar, ez}`.

**Таймер отдыха.** Кнопки −30, −15, +15, +30 с и «Пропустить». Без звука и без удержания экрана.

**Анимация.** При входе на «Прогресс» линии прорисовываются, точки и клетки проявляются; при `prefers-reduced-motion` анимации нет. Порядок появления задаётся через CSSOM (`paintStagger`): политика CSP страницы запрещает инлайн-стили.

Проверка: `node tests/stats-unit.cjs` — адаптивные недели, темп, прогноз, тренд, рабочие подходы, подсчёт по мышцам, блины, логарифмическая кривая, индекс силы, SVG.

## Тренировка и еда · версия 13

**Тренировка.** У каждого подхода серым стоит цель: на входе в цикл — вес недели из программы (`start`), дальше — двойная прогрессия от прошлой тренировки: рабочий вес и +1 повтор, а при верхней границе во всех подходах — прибавка `inc` и нижняя граница повторов. Кнопка ✓ записывает цель (или введённые числа) и запускает таймер отдыха по `rest` упражнения; повторное нажатие запись не стирает. Сверху счётчик и полоса подходов, внизу «Закончить тренировку» — итог: подходы, объём, новые максимумы по оценке 1ПМ. Техника спрятана в «Как делать».

**Еда.** У каждого приёма сразу поле текста; ввод создаёт запись, очистка удаляет её. «Как вчера» копирует вчерашний приём, «Не ел» отмечает пропуск, вариант из плана и ккал/белок — в раскрывающемся блоке. Сверху: сколько приёмов записано и оценка разбора за день, если она есть; суммы «~0 ккал» больше нет. Неделя показывает записанные приёмы и ккал из разбора. Добавки — переключатели в одну строку.

## Экран «Сегодня» · версия 12

Вкладка «Обзор» стала «Сегодня». Одна дата на весь экран, сверху вниз: полоска недели (нажатие выбирает день), план дня с одной кнопкой (начать или открыть тренировку, записать бег), «Утро» — прежняя форма веса, сна, шагов и замеров с кнопкой «Сохранить», самочувствие 1–5 одним касанием (`body/ГГГГ-ММ.json → mood`, повторное касание снимает отметку), «Ещё за день» — еда, добавки и воскресный замер со ссылками, строка недели со ссылкой на «Прогресс».

Блок «Твои результаты» перенесён на «Прогресс». На вкладке «Тренировка» больше нет второго поля веса, сна и шагов: они вводятся на «Сегодня» или в «Вес и замеры». Предупреждение о сне меньше 6 часов осталось.

## Вкладка «Прогресс» · версия 11

Четвёртая вкладка собирает недельные цели и графики. Расчёты и SVG — в `stats.js` (без сети и хранилища), отрисовка — `renderStats()` в `app.js`.

- **Цели недели** — кольца: залы, бег, среднее шагов (завершённые дни), среднее сна, белок из разбора питания, вес в коридоре.
- **Вес** — утренние замеры, среднее за 7 дней (от 4 замеров), коридор каждой недели цикла и линия плана. Цель недели k: `base − perWeek·(k−1)`, коридор `band` из `program.json → goals.weight`. Среднее недели считается от 4 замеров, меньше — показывается как предварительное.
- **Постоянство** — сетка цикла: зал, бег, пропуск запланированного, план.
- **Сила** — оценка 1ПМ по Эпли `вес × (1 + повторы/30)` для упражнений из `goals.lifts`; подходы больше 15 повторов не учитываются. Замена — отдельное упражнение со своей историей.
- **Объём** — вес × повторы за тренировку; подходы без веса не входят.
- **Восстановление** — шаги и сон за 14 дней с линией цели; пропущенный день не рисуется.
- **Питание** — среднее ккал и белка за последнюю неделю из `food/estimates/ГГГГ-ММ.json` (оценки разбора, только полные дни). Журнал эти файлы только читает.
- **Талия / рост** — последний замер талии и `goals.heightCm`.

Проверка: `node tests/stats-unit.cjs` (расчёты и SVG) и прежние наборы.

## Активность и автоматическая отправка · версия 10

`SPORT_HEALTH_V1` принимает необязательные `activeKcal` (активная энергия за день, ккал) и `exerciseMin` (время упражнений, мин). Пустое значение — неизвестно, не ноль; дробные и с запятой округляются. Старые тексты без этих полей читаются как раньше.

Команда iPhone может сама положить свой текст в приватный репозиторий как `health/auto/ДАТА.txt` (раздел 8–9 `health-setup.html`). Журнал загружает такие файлы при обычной синхронизации, проверяет тем же `health.js` и никогда их не пишет. Файл, который не прошёл проверку или чья дата не совпадает с именем, не учитывается. Приоритет: ручной ввод → подтверждённый импорт вставкой → автоматический файл. На «Обзоре» под шагами появляется строка «Часы: активные … ккал · упражнения … мин».

Для отправки команде нужен отдельный fine-grained токен только на этот репозиторий с правом Contents: Read and write. Токен журнала в команду не передаётся. Тренировки Apple Watch пока не импортируются: доступность типа Workouts в «Командах» нужно проверить на телефоне.

Проверка: `node tests/health.cjs` — разбор активности, чтение автоматических файлов через GitHub pull, приоритет импорта, игнорирование неверного файла, отсутствие записи в очередь.

## Сон и шаги · версия 8

В настройках появился импорт результата встроенной команды iPhone. Полный порядок сборки команды и проверки результата находится в `health-setup.html` (доступен и без сети после обновления). Это полуавтоматический путь: команда читает Health и копирует текст, пользователь вставляет его в установленный журнал и подтверждает импорт. Команда не получает токен и не отправляет данные в сеть. Журнал синхронизирует только подготовленные записи через прежнее подключение GitHub. Доступ к HealthKit напрямую из сайта, фоновые отправки и импорт тренировок не реализованы.

`health.js` принимает `SPORT_HEALTH_V1` или JSON `sport-health.v1` за один завершённый день. Шаги — число из одного выбранного Watch-источника, сон — интервалы с ISO 8601 и категорией. Суммируется объединение интервалов сна в окне с полудня предыдущего дня до полудня выбранного; In Bed/Awake не добавляются. Источник сна в Shortcuts требует проверки на телефоне, поэтому общий источник в инструкции обозначен Apple Health. Итог шагов только часов может отличаться от объединённого итога iPhone и часов.

Импорт записывается в отдельный `health/` файл. Ручные значения, включая 0, имеют приоритет. Повтор идентичных данных ничего не меняет. Отсутствующее значение не стирает предыдущий импорт. Неизвестная категория, ошибочная дата или полностью пустой результат останавливают импорт до записи. Экспорт и резервная копия включают Health-файлы; остальная схема и ключ хранилища сохранены.

Проверка: `node tests/health.cjs`. Используются синтетические данные, изолированный профиль браузера и локальный сервер. Реальная команда, разрешения Health и буфер обмена Safari/PWA на физическом iPhone требуют отдельной проверки.

В разделах «Обзор», «Тренировка», «Еда» и «Вес и замеры» можно нажать на дату, чтобы раскрыть календарь. В нём есть переключение месяцев, выделение выбранного дня и кнопка «Сегодня». Стрелки рядом с датой по-прежнему переключают дни. Календарь работает без сети. Для управления с клавиатуры доступны стрелки, Home/End, PageUp/PageDown и Escape.

Для телефона задано `touch-action: manipulation`: двойной тап не должен увеличивать страницу, прокрутка и масштабирование двумя пальцами сохраняются. Поля ввода имеют размер шрифта от 16 px.

## Проверка мобильного интерфейса

При установленном Node.js, Playwright и Chrome: `node tests/mobile.cjs`. Если Playwright находится в отдельном каталоге, укажи его через `NODE_PATH`. Для сохранения скриншотов задай `TEST_ARTIFACT_DIR` вне репозитория приложения.

Проверки используют отдельный профиль браузера, синтетические записи и локальный HTTP-сервер. Проверяются выбор дат, сохранение записей, високосный год, клавиатура, восемь размеров экрана, обе темы и работа без сети. Настоящий токен и приватный GitHub не нужны. Поведение Safari, жестов и клавиатуры на физическом iPhone проверяется отдельно.

`node tests/data-preservation.cjs` проверяет старый формат, очередь отправки, неизвестные поля, резервные копии, конфликт GitHub и ввод во время загрузки. `PREVIOUS_APP_REF=15ef68eaf28ce2aa3e703e165738f0b61bf506ac` задаёт опубликованную старую версию для проверки обновления service worker v5 → v7 без потери локальных записей.
